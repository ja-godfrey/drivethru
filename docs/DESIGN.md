# drivethru design

drivethru fuzzy-finds anything in the Google Drive for desktop folders on a Mac
and hands you its web link: copy the share link, open it in the browser as the
right Google account, or reveal it in Finder. It never talks to Google. Every
link is built from metadata Drive for desktop already keeps on disk, so there
is no OAuth, no API key, and no network call to resolve a link. Local file
permissions and existing Drive sharing restrictions still apply.

This document is the contract for the implementation and the tests.

## Platform

- macOS 13 or later (Drive for desktop itself requires 13+ since v127).
- `#!/bin/bash`, and the code must run on the stock `/bin/bash` 3.2.57. No
  associative arrays, `mapfile`, `${x,,}`, `${x^^}`, namerefs, `;&`, `|&`,
  negative array indexes. Empty arrays under `set -u` are expanded as
  `${a[@]+"${a[@]}"}`. Use `printf`, never `echo` with data.
- ShellCheck-clean with `shellcheck -s bash`.
- Runtime dependencies: `fzf` (0.42+, for the picker and `search`) plus
  stock tools only: `xattr`, `plutil`, `sqlite3`, `pbcopy`, `open`, `osascript`,
  `find`, `stat`, `realpath`, `fileproviderctl`, `mktemp`, and the equally
  stock `iconv`, `nohup`, `logger`, `sw_vers`, `pbs`, `sed`, `tr`, `grep`, `head`.
  `/usr/bin/jq` (macOS 15+) is used when present, with an
  `osascript -l JavaScript` (JXA) fallback. Never call `python3`: on a stock
  Mac `/usr/bin/python3` is the Command Line Tools installer stub and pops a
  GUI dialog.
- Call system tools by absolute path (`/usr/bin/xattr`, `/usr/bin/plutil`, …)
  so a user's Homebrew GNU tools or Python `xattr` package can't change
  behaviour.
- The script sets its own PATH prefix (`/opt/homebrew/bin:/usr/local/bin:
  /opt/local/bin:$HOME/.local/bin:$HOME/.fzf/bin:$HOME/.nix-profile/bin`) before looking up `fzf`, because hotkey
  tools start processes with `/usr/bin:/bin:/usr/sbin:/sbin`.
- Before fzf runs any `--preview`/`--bind` command, `export SHELL=/bin/bash`
  (fzf runs them with `$SHELL`, which may be zsh or fish).

## Where Drive lives on disk

- One mount per signed-in account: `$DRIVETHRU_ROOT/GoogleDrive-<email>/`,
  where `DRIVETHRU_ROOT` defaults to `$HOME/Library/CloudStorage`. Always
  derive from `$HOME`, never from `getpwuid`/`dscl` (the Homebrew test
  sandbox sets `HOME` to a temp dir).
- Mount contents: a My Drive folder, a Shared drives container (may be empty,
  may be absent), possibly an Other computers container, and hidden
  bookkeeping folders (`.shortcut-targets-by-id`, `.Trash`, `.tmp`,
  `.Encrypted`) plus `.DS_Store` files.
- **Folder names are localized** ("Meine Ablage", "Mi unidad", …), and an admin
  policy can force English. Never hard-code "My Drive" or "Shared drives".
  Identify by structure:
  - My Drive root = the non-hidden depth-1 directory of a mount that HAS an
    item id.
  - Virtual containers (Shared drives, Other computers) = non-hidden depth-1
    directories WITHOUT an item id.
  - Shared-drive roots = depth-2 directories under the Shared drives container;
    children of the Other computers container are computer backup folders.
- Legacy `/Volumes/GoogleDrive*` mounts (pre-File-Provider) are out of scope
  for 0.1; `doctor` should mention them if present.

## Drive item ids

- Most synced files and folders carry the xattr
  `com.google.drivefs.item-id#S` (the `#S` is part of the name; always
  single-quote it). Value is raw ASCII `[A-Za-z0-9_-]+`, no newline. Read with
  `/usr/bin/xattr -p 'com.google.drivefs.item-id#S' "$path" 2>/dev/null`.
  Do not validate by length (19, 28, 32, 33, 35, 44, 49, 57, 72, 73 all occur).
- Read ids lazily: only for the item(s) the user selects, or for the preview
  of the highlighted row. Never in bulk while listing.
- Never read file contents in bulk. Reading a placeholder materializes it.
  Reading one small stub JSON for the selected item is fine.
- Items without an id: the mount root, virtual containers, hidden bookkeeping
  folders, `.DS_Store`, and files created locally that haven't uploaded yet.
  For a regular item with no id, say "not uploaded to Drive yet" (exit 3),
  unless the database check knows the item: some uploaded files never get the
  xattr (see Implementation notes).
- **Only trust ids for paths under a detected mount.** `cp`/`ditto` copy the
  xattr, so a file on the Desktop can carry some Drive file's id.
- **Copies made inside Drive can keep the source file's id even after they
  upload and get their own.** The xattr alone can therefore point at the wrong
  file. The optional database check below catches this.

## Google-native placeholders

Drive for desktop represents Google-native files as small JSON stubs:

    {"":"WARNING! DO NOT EDIT THIS FILE! ANY CHANGES MADE WILL BE LOST!",
     "doc_id":"…","resource_key":"…","email":"…"}

Extensions (authoritative list: `CFBundleDocumentTypes` in
`/Applications/Google Drive.app/Contents/Info.plist`): gdoc, gsheet, gslides,
gform, gdraw, gscript, gmap, gsite, gjam, gvid, gtable, gnote, gmaillayout,
glink, gprj, gpic, gcse, gdrive. `.gs` and `.geojson` are ordinary files.

`NAME.EXT.gdrive` is a stub for a non-downloadable file (owner blocked
download), same JSON schema.

For a selected stub, read `doc_id` and `resource_key` with
`/usr/bin/plutil -extract doc_id raw -o - FILE` (always pass `-o -`; without it
`-extract` rewrites the file). `raw` fails on JSON null; treat any failure as
"no value".

## Shortcuts

A Drive shortcut appears in one of four forms:

1. Symlink to the target's absolute path inside the same mount.
2. Symlink into `<mount>/.shortcut-targets-by-id/<id>/<name>`.
3. Broken symlink: empty `readlink`, `xattr -p` fails. Target unknown or
   inaccessible.
4. A regular file standing in for a target that has no visible parent:
   `.gdoc`/`.gsheet`/… or `.gdrive` stubs whose xattr is the SHORTCUT id and
   whose JSON `doc_id` is the TARGET id; or binary stand-ins (pdf, docx, …)
   whose xattr is the shortcut id, where only the database knows the target.

Share links must point at the TARGET (a shortcut's ACL inherits its parent
folder's, so recipients often can't open the shortcut id). Rules:

- Symlink (1, 2): `xattr -p` without `-s` follows to the target: use it.
  Derive the kind from the resolved target (`-d`, target file name extension).
  If the target is itself a form-4 stand-in, resolve it as one (the database
  gives the real target).
- Broken symlink (3): `xattr -s -p` gives the shortcut's own id. Use
  `https://drive.google.com/open?id=ID`, and warn "shortcut target isn't
  available locally; this link points at the shortcut" (still exit 0).
- Regular stub (4): prefer JSON `doc_id` over the xattr when they differ,
  unless the database identifies the selected path as a non-shortcut with its
  own authoritative id. A copied stub can retain the source's JSON even when
  its xattr is missing.
- Binary stand-in (4): resolved only by the database check.
- The file list must not follow symlinks (`find` default `-P`); targets are
  absolute paths and following would duplicate trees or loop.

## Link templates

share_url(kind, id[, resource_key]):

| kind | URL |
| --- | --- |
| folder, shared-drive root | `https://drive.google.com/drive/folders/ID` |
| gdoc | `https://docs.google.com/document/d/ID/edit` |
| gsheet | `https://docs.google.com/spreadsheets/d/ID/edit` |
| gslides | `https://docs.google.com/presentation/d/ID/edit` |
| gform | `https://docs.google.com/forms/d/ID/edit` (editor link; say so) |
| gdraw | `https://docs.google.com/drawings/d/ID/edit` |
| gscript | `https://script.google.com/d/ID/edit` |
| gmap | `https://www.google.com/maps/d/edit?mid=ID` |
| gdrive stub | `https://drive.google.com/file/d/ID/view` |
| other g* stubs | `https://drive.google.com/open?id=ID` |
| any other file | `https://drive.google.com/file/d/ID/view` |
| broken shortcut | `https://drive.google.com/open?id=ID` |

- Resource key: when known and matching `^[0-9]-[A-Za-z0-9_-]{22}$`, append
  `resourcekey=KEY` (lowercase parameter name; `?` or `&` as appropriate).
  Never guess a key. If the id starts with `0B` and no key was found, warn
  "legacy item: people who haven't opened it before may need a resource key
  that drivethru couldn't read".
- My Drive root: no share link (error "My Drive itself can't be shared", exit
  4). Open URL: `https://drive.google.com/drive/my-drive`.
- Virtual containers: no share link (exit 4). Open URL for the Shared drives
  container: `https://drive.google.com/drive/shared-drives`; otherwise
  `https://drive.google.com/`.
- Copied links stay clean: no `authuser`, no `usp`.
- open_url(share_url, email) = share_url plus `authuser=<email>` (`?`/`&`),
  applied to the final type-specific URL. (`open?id=` drops `authuser` when it
  redirects; for those rare kinds that is accepted.)

## Optional database check (DriveFS metadata)

Drive for desktop keeps a private SQLite database per account. drivethru may
read it, read-only, for the selected item(s) only, to:

1. catch ids inherited by copies (the xattr points at another file),
2. resolve binary shortcut stand-ins to their target,
3. read resource keys of legacy (`0B…`) items.

Facts:

- Account dir: `$DRIVETHRU_DRIVEFS_DIR/<N>/` (default
  `$HOME/Library/Application Support/Google/DriveFS`), where `<N>` is the
  suffix of the mount root's `com.apple.file-provider-domain-id` xattr, whose
  value looks like `com.google.drivefs.fpext/gdrive-<N>`. Also
  `DriveFS/<N>/my-drive` is a symlink to that mount's My Drive folder.
- Database: `DriveFS/<N>/metadata_sqlite_db` (+ `-wal`, `-shm`). Table `items`
  has `id` (cloud id), `proto`, `mime_type`, `is_folder`, `local_title`, and
  more; tables `stable_ids`, `stable_parents`, `shortcut_details` exist. The
  implementation must inspect the real schema before relying on it.
- `items.proto` is stored with TEXT affinity: use `CAST(proto AS BLOB)`.
  Resource key = protobuf field 140, bytes `E2 08 18` then 24 ASCII bytes
  `[0-9]-…`: `CAST(substr(CAST(proto AS BLOB), instr(CAST(proto AS BLOB),
  X'E20818')+3, 24) AS TEXT)` (validate the regex after extraction). Shortcut
  target id = field 132.1, target resource key = field 132.7; the
  `shortcut_details` table joined to `stable_ids` also gives the target.
- `/usr/bin/fileproviderctl evaluate PATH` (~16 ms) prints the File Provider
  item identifier (= `items.stable_id`) and upload state for one path. With
  `stable_ids`, that maps to the authoritative cloud id.
- Opening the live DB, even `mode=ro`, writes its WAL index and makes macOS tag
  files. Therefore: copy `metadata_sqlite_db` and its `-wal`/`-shm` into a
  private temp dir (`mktemp -d`, mode 700), query the copy, delete it on exit
  (trap). If anything fails (DB missing, schema differs, integrity error) fall
  back silently to xattr-only behaviour; explain under `DRIVETHRU_DEBUG=1`.
- Names can differ between disk and DB only by Unicode normalization (NFD vs
  NFC). Normalize before comparing.
- The schema is undocumented and can change. Everything here is
  best-effort, and `db = off` in the config disables it.

## Browser routing (open)

- Account email = the part after `GoogleDrive-` in the mount folder name.
- `browser = auto` (default): if a Google Chrome channel (bundle ids
  `com.google.Chrome`, `.beta`, `.dev`, `.canary`) is installed and one of its
  profiles belongs to the email, open there; otherwise open in the default
  browser with `authuser=<email>`.
  - Profile lookup: Local State (`<UserDataDir>/Local State`)
    `profile.info_cache[<dir>].user_name` (primary account), then
    `<UserDataDir>/<dir>/Preferences` `account_info[].email` (other accounts
    signed in on the web). Compare case-insensitively; treat `googlemail.com`
    as `gmail.com`, and for gmail ignore dots in the local part.
  - List profiles from `info_cache` keys only (not directory globbing; skip
    "System Profile"/"Guest Profile").
  - JSON parsing: `/usr/bin/jq` when executable (write jq-1.6-compatible
    filters, no regex builtins), else JXA (`osascript -l JavaScript`, reading
    with NSString; JXA doesn't expand `~`, pass absolute paths).
  - Launch: `/usr/bin/open -n -b <bundle-id> --args
    --profile-directory=<dir> --ignore-profile-directory-if-not-exists
    --profile-email=<email> <url>` (the extra switches make a stale dir fall
    back to the email, then to the last-used profile, and never create a new
    empty profile). The implementation must verify this launch form end to end
    on a real Mac once; if it misbehaves when Chrome is running, fall back to
    executing the Chrome binary directly with the same arguments, detached
    with `nohup … &`.
- `browser = chrome|chrome-beta|chrome-dev|chrome-canary`: force that channel
  (profile lookup as above). `browser = default`: always default browser +
  `authuser`.
- Default browser: JXA `NSWorkspace.URLForApplicationToOpenURL` for an https
  URL; fall back to `open URL`.
- Test hook: `DRIVETHRU_CHROME_DIR` overrides the Chrome user-data dir.
- After opening, run the optional `after_open` config command with
  `/bin/bash -c` and env `DRIVETHRU_EMAIL`, `DRIVETHRU_URL`,
  `DRIVETHRU_PROFILE_DIR` (empty when not Chrome). This lets window-manager
  users focus the tab's window.

## Command line

    drivethru [pick] [QUERY]      interactive picker (needs a terminal)
    drivethru popup [QUERY]       open the picker in a new terminal window
    drivethru link [OPTS] PATH…   print share links for paths
    drivethru open PATH…          open paths in the browser as their account
    drivethru search [OPTS] QUERY non-interactive fuzzy search (no terminal)
    drivethru list                print every indexed item
    drivethru doctor              check the setup and explain problems
    drivethru install-quick-action  install the Finder Quick Action
    drivethru --help | --version

- `link` options: `--copy` (also put the result on the clipboard), `--markdown`
  (`[name](url)` per line), `--notify` (macOS notification with the result),
  `--` ends options. Accepts paths through any symlink (e.g.
  `~/you@example.com - Google Drive/…`): canonicalize the parent directory
  with `realpath` and keep a final symlink as-is (so a shortcut symlink is
  classified as a shortcut, not silently replaced by its target path).
- `search` options: `--limit N` (default 10), `--links` (append the share link
  column; reads ids for the N results only), `--copy-first` (copy the top
  result's link, print it, exit), `-0`/`--null` (NUL-terminated records),
  `--` ends options. Default output lines:
  `label<TAB>relative/path` (plus `<TAB>url` with `--links`).
- `list` output: one `label<TAB>relative/path` per line, or per NUL record
  with `-0`/`--null`.
- Exit codes: 0 ok; 1 usage/config/action error, missing path or no copy-first match; 2 no Drive mounts found; 3 item has
  no Drive id (not uploaded, or not under a mount); 4 no share link for this
  kind of item (My Drive root, virtual container); 5 missing/failing dependency;
  6 denied target or no readable mount (File Provider consent); 130 cancelled.
  Partially denied listings warn and continue with readable accounts.
- stdout carries only results; messages go to stderr.

### Picker

- Rows: `label<TAB>relative/path` read NUL-delimited (`find … -print0`,
  `fzf --read0 --print0`) so names with newlines are safe. The label must be a
  displayed and searchable field so typing the account name filters to it.
- Listing: one `find` per mount, streamed into fzf so results appear
  immediately; prune every name starting with `.` and the `Icon\r` file; never
  follow symlinks. ~120k items should list in under 2 s.
- Keys: `enter` copy link(s); `ctrl-o` open in browser; `ctrl-f` reveal in
  Finder (`open -R`); `ctrl-y` copy as Markdown links; `tab`/`shift-tab`
  multi-select (every action applies to all selected rows); `esc` cancel.
- Header shows the keys. `--layout=reverse --scheme=path --cycle
  --info=inline-right`.
- Preview (bottom, ~3 lines, wrapping): kind (Google Doc, Sheet, Slides, Form,
  folder, shared drive, PDF…), account email, modified date (`stat`), and
  "Link resolved when copied or opened". This lightweight preview never reads
  file contents or the database, so it must not advertise an unverified URL
  or label a missing xattr as proof that an item has not uploaded. Toggle with
  `ctrl-p`. Copy/open performs full resolution for the selected items.
- If the terminal check `{ : </dev/tty; } 2>/dev/null` fails, do NOT start fzf
  (it hangs without a TTY). Print "drivethru needs a terminal; use `drivethru
  popup` from hotkeys" and exit 1. Do not use `[ -t 1 ]` for this.
- fzf with `--expect`: Esc/ctrl-c exit 130 and print nothing; check the exit
  status before parsing.

### Popup

- Terminal: `terminal` config / `DRIVETHRU_TERMINAL`, else auto-detect
  installed apps in order Ghostty (`com.mitchellh.ghostty`), kitty
  (`net.kovidgoyal.kitty`), WezTerm (`com.github.wez.wezterm`), Alacritty
  (`org.alacritty`), iTerm2 (`com.googlecode.iterm2`), Terminal
  (`com.apple.Terminal`).
- Size: `popup_size` config, default `130x26`.
- Commands (the popup runs `drivethru --in-popup [QUERY]` by absolute path):
  - Ghostty: `open -na Ghostty --args --window-width=W --window-height=H
    --title=drivethru --confirm-close-surface=false --window-save-state=never
    --quit-after-last-window-closed=true -e ABS --in-popup …` (all flags
    before `-e`).
  - kitty: `open -na kitty --args -o remember_window_size=no
    -o initial_window_width=Wc -o initial_window_height=Hc
    -o macos_quit_when_last_window_closed=yes -o confirm_os_window_close=0
    --title drivethru ABS --in-popup …`
  - WezTerm: `open -na WezTerm --args --config initial_cols=W
    --config initial_rows=H start --always-new-process -- ABS --in-popup …`
  - Alacritty: `open -na Alacritty --args -o window.dimensions.columns=W
    -o window.dimensions.lines=H -T drivethru -e ABS --in-popup …`
  - iTerm2 and Terminal: AppleScript (Terminal leaves the window open;
    close it after the command ends; document the Automation prompt).
- `--in-popup` behaviour: after a successful copy, print "Copied: NAME" for
  ~0.6 s then exit; on an error or warning (including an unreadable account),
  print it and wait for a key before the window closes. If `aerospace` is on PATH and the focused window belongs to
  the popup terminal, run `aerospace layout floating` first (tiling WMs).
- The launcher must return immediately (hotkey tools kill or wait on
  long-running commands).

## Account labels and config

- Default label: for gmail.com/googlemail.com addresses, the local part; for
  other domains, the first label of the domain (`umich.edu` → `umich`). On a
  collision, use the full email for all colliding accounts.
- Config file: `$DRIVETHRU_CONFIG` or `~/.config/drivethru/config`.
  `key = value` lines, `#` comments, blank lines ignored; never `source`d or
  `eval`ed (only `after_open` is executed, deliberately).

      label.you@example.edu = school
      browser = auto
      terminal = ghostty
      popup_size = 130x26
      db = auto            # auto | off
      after_open = aerospace-focus-script
      notify = false

- Unknown keys: warn under `doctor`, ignore otherwise.

## Test hooks

- `DRIVETHRU_ROOT` (fake CloudStorage dir), `DRIVETHRU_DRIVEFS_DIR`,
  `DRIVETHRU_CHROME_DIR`, `DRIVETHRU_CONFIG`.
- `DRIVETHRU_DRY_RUN=1`: instead of `pbcopy`, `open`, `osascript`, launching a
  browser or terminal, print what would happen to stderr as
  `drivethru: dry-run: <action> <args…>` and, for clipboard writes, write the
  clipboard text to `$DRIVETHRU_CLIPBOARD_FILE` if set.
- `DRIVETHRU_DEBUG=1`: trace decisions (id source, DB use) to stderr.
- `DRIVETHRU_JQ`: path used instead of `/usr/bin/jq` (a nonexistent path forces
  the JXA fallback). `DRIVETHRU_FZF`: path used instead of looking `fzf` up on
  PATH (a nonexistent path means "fzf missing", exit 5); needed because the
  script always puts the Homebrew prefixes on PATH.
- `fileproviderctl` is only used when the path is under the real
  `$HOME/Library/CloudStorage`; the fixture tree never calls it.

## Privacy

- drivethru prints nothing about files except what the user asked for.
- Database copies live in a private temp dir and are removed on exit, including
  on Ctrl-C.
- The demo GIF and tests use a synthetic Drive tree only.

## Implementation notes

Verified by the core implementation on macOS 26.5.1, Drive for desktop 131.0,
Chrome 154 and four real accounts. Only counts were recorded; no names, ids or
emails.

### DriveFS database

- All four account DBs have the same schema. Tables: `activity_items`,
  `deleted_items`, `folder_features`, `item_properties`, `item_workspaces`,
  `items`, `local_stable_ids`, `operations`, `properties`, `queries`,
  `shortcut_details`, `stable_ids`, `stable_parents`, `teamdrive_query`,
  `workspaces`.
- What drivethru relies on (checked before every use; any mismatch means
  "ignore the DB"):
  - `items(stable_id INTEGER PRIMARY KEY, id TEXT UNIQUE, proto BLOB,
    mime_type TEXT, is_folder, local_title TEXT, is_tombstone, ...)`. `id` is
    the cloud id. `proto` has TEXT storage class in every row, so byte
    functions need `CAST(proto AS BLOB)`.
  - `stable_ids(stable_id INTEGER PRIMARY KEY, cloud_id TEXT)`: a superset of
    `items` (it also holds shortcut targets that have no `items` row).
    `items.stable_id = stable_ids.stable_id` and `cloud_id = items.id` for
    every row.
  - `stable_parents(item_stable_id, parent_stable_id, local_title_hash)`.
  - `shortcut_details(shortcut_stable_id PRIMARY KEY, target_stable_id,
    target_mime_type)`.
- `local_title` is the on-disk name, including the placeholder extension (a
  Doc is `Plan.gdoc`). It can differ from the disk name only by Unicode
  normalization: 6 of about 190 sampled non-ASCII names did.
  `/usr/bin/iconv -f UTF-8-MAC -t UTF-8` (NFC) and the reverse (NFD) are
  enough; drivethru matches `local_title IN (name, NFC, NFD)`.
- Copying: `cp -c` (an APFS clone) of `metadata_sqlite_db`, `-wal` and `-shm`
  into a `mktemp -d` dir is instant even for a 130 MB DB and leaves the live
  files untouched. Plain `cp` is the fallback. Queries use
  `sqlite3 -init /dev/null` so a user's `~/.sqliterc` can't change the output,
  and `|` as the column separator: a TAB is IFS whitespace, so `read` would
  collapse empty columns.
- Query (a), cloud id to mime and resource key: `SELECT mime_type, <key> FROM
  items WHERE id = ? AND is_tombstone = 0`. The key is
  `CAST(substr(b, instr(b, X'E20818') + 3, 24) AS TEXT)` with
  `b = CAST(proto AS BLOB)`, kept only if it matches the GLOB
  `[0-9]-` followed by 22 `[A-Za-z0-9_-]`.
- Query (b), shortcut to target: `items LEFT JOIN shortcut_details ON
  shortcut_stable_id = items.stable_id LEFT JOIN stable_ids ON stable_id =
  target_stable_id` gives the target id and mime. The target's key is the
  target row's own field 140, or else field 132.7 of the shortcut: the first
  `X'3A18'` after the first `X'A208'` (the field-132 tag), then 24 bytes.
- Query (c), the authoritative id of a path:
  1. Real mounts only: `fileproviderctl evaluate PATH`, line
     `itemIdentifier = N;` (an integer, `items.stable_id`), then
     `stable_ids.cloud_id`.
  2. Any tree (this is what the fixture exercises): the parent folder's xattr
     id, then `items p JOIN stable_parents sp ON sp.parent_stable_id =
     p.stable_id JOIN items c ON c.stable_id = sp.item_stable_id WHERE p.id = ?
     AND c.is_tombstone = 0 AND c.local_title IN (...)`. With exactly one row,
     that id is authoritative. With several, the xattr is kept if it is one of
     them.

  When the authoritative id differs from the xattr, it wins, and a stub's JSON
  is ignored too (the copy copied it). When the xattr is missing, the
  authoritative id is used if the DB has one; only then is an item "not
  uploaded".
- Measured on the real DBs:
  - 160 random regular files (40 per account): the File Provider id equalled
    the xattr in 160/160, and the parent+title lookup agreed in 160/160.
  - Inherited ids: in one account, 16 ids appear on 46 regular files. The
    File Provider id showed 16 originals and 30 copies carrying another
    file's id. The parent+title lookup agreed on all 46. `drivethru link` gives
    the DB id for all 30 copies and the xattr id for all 16 originals.
  - 23 uploaded files (File Provider `isUploaded = 1`) had no item-id xattr at
    all. The DB knew all 23, and `drivethru link` now links them.
  - Shortcuts: 28 binary stand-ins across the accounts (regular non-stub files
    whose id has mime `application/vnd.google-apps.shortcut`) resolved to their
    DB target, 28/28. 24 sampled symlink shortcuts gave the followed id,
    except 2 whose target is itself a regular-file stand-in; for those,
    drivethru follows the DB on to the real target (2/2). 15 broken symlinks
    gave `open?id=` with their own id (15/15).
  - Resource keys: every `0B` id in the DBs has a field-140 key (332 items),
    and nothing else does. Field 132.7 is present on 3 shortcuts and equals the
    target's own key wherever both exist (2/2). `drivethru link` added the key
    for 9/9 sampled `0B` files and 6/6 `0B` folders.
  - 15 Google-native stubs gave `doc_id` (15/15), 40 regular files and 28
    folders or shared-drive roots gave their xattr id (all matched), and every
    My Drive root and container exited 4 (6/6).
- Directories under `.Encrypted` carry `com.google.drivefs.cse-target-item-id#S`
  instead of the item id. The listing prunes them anyway.

### fileproviderctl

- `fileproviderctl evaluate PATH` takes about 16 ms and prints a
  property-list-style dump: `Evaluating actions against {`, then
  `domainUserInfo`, then `fileproviderItems = ( { ... } )`, whose item has
  `itemIdentifier`, `parentItemIdentifier`, `isUploaded`, `isUploading`,
  `isFolder`, `isTrashed`, `typeIdentifier`, `userInfo` (with
  `ACTION_COPY_LINK`, `SHARED_DRIVE_ROOT`, ...) and more. An `Actions:` list
  follows.
- `itemIdentifier` is an integer for Drive items. The mount root is
  `NSFileProviderRootContainerItemIdentifier`, and the Shared drives container
  is `DFSFileProviderSharedDrivesIdentifier`. drivethru uses the latter to
  tell that container apart on real mounts; elsewhere it looks for a child
  folder whose id starts with `0A`.
- For a path outside any File Provider domain, it prints `No item for URL` and
  an `NSFileProviderErrorDomain` error but still exits 0. Parse the output;
  never trust the exit status.

### Chrome launch (verified once, end to end)

- `/usr/bin/open -n -b com.google.Chrome --args --profile-directory=<dir>
  --ignore-profile-directory-if-not-exists --profile-email=<email> <url>` was
  run with Chrome running. The chosen profile was open but was not the
  last-used one. The URL showed up in that profile's History (a copy was
  queried) and in no other profile's. No fallback to the Chrome binary is
  needed.
- The test tab could not be closed with AppleScript. Apple Events from the
  agent's process timed out (-1712); an Automation consent was pending. So the
  iTerm2 and Terminal popup AppleScripts are only dry-run tested. Both need the
  Automation permission for the calling app ("X wants to control Terminal").

### Behaviour details for tests and contributors

- Listing: in each mount, `find -f TOP ... \( -name '.*' -o -name $'Icon\r' \)
  -prune -o -exec /usr/bin/printf 'LABEL\t%s\0' {} +`, where the TOP entries
  are the mount's non-hidden children and `-f` is safe for names starting
  with `-`. It lists 118,300 real items in about 0.8 s. A warm `link` with the
  DB check takes about 0.1 s.
- Temp files go to `$TMPDIR/drivethru.XXXXXXXX`, mode 700.
  `mktemp -d -t` isn't used because on macOS it ignores `$TMPDIR`.
- `DRIVETHRU_DRY_RUN=1` replaces actions only. Read-only queries still run:
  JXA NSWorkspace lookups of the default browser and installed apps, and jq or
  JXA on `Local State`. The dry-run labels are `open`, `pbcopy`, `notify`,
  `osascript <iterm2|terminal> <command> WxH`, `aerospace`, `install` and
  `pbs`. `after_open` is logged under dry-run and never executed.
- When `DRIVETHRU_CHROME_DIR` is set, that dir is the user-data dir of the
  configured channel (`com.google.Chrome` for `auto`), and installed-app
  detection is skipped. `DRIVETHRU_JQ` overrides `/usr/bin/jq`; point it at a
  nonexistent path to exercise the JXA fallback.
- Config: junk lines and unknown keys are ignored silently, and `doctor` lists
  them. An invalid value for a known key is a config error (exit 1) for every
  command except `doctor`, `--help` and `--version`.
- The mount root exits 4 (`open` goes to `https://drive.google.com/`). An item
  inside a hidden bookkeeping folder that has no id exits 3 with its own
  message.
- `list` and `search` support `-0` / `--null` to preserve embedded filename
  newlines in NUL-terminated records. The default newline format is for human
  use; `search --copy-first` always prints a single newline-terminated URL.
- Both fzf invocations clear `FZF_DEFAULT_OPTS` and `FZF_DEFAULT_OPTS_FILE`;
  personal bindings/output options must not alter the command protocol.
- `search` with no match prints nothing and exits 0. `search --copy-first`
  with no match exits 1.
- fzf exit status 1 (Enter with no match) is treated like Esc: exit 130,
  nothing printed. In the picker, Enter and ctrl-y print the link(s) to
  stdout and `Copied: NAME` to stderr.
- `install-quick-action` copies `share/drivethru/*.workflow` (looked up next to
  the script's real path, then in `../share/drivethru`) into
  `~/Library/Services` and runs `pbs -update`. When `drivethru` isn't in
  `/opt/homebrew/bin` or `/usr/local/bin`, it rewrites the installed copy's
  `drivethru link` to the absolute path of the running script.
- The `--in-popup` AeroSpace float runs in the background: for up to 2 s it
  waits for the focused window's bundle id to match the terminal (found from
  `TERM_PROGRAM`, `KITTY_WINDOW_ID` or `ALACRITTY_WINDOW_ID`), then runs
  `aerospace layout floating`.

### Release review corrections

- Paths use `realpath` to normalize case and volume aliases before mount
  comparisons; final shortcut symlinks are preserved until resolution.
- Database validation checks columns on all four queried tables, including
  `stable_parents` and `shortcut_details`. SQL failures appear with
  `DRIVETHRU_DEBUG=1`; incompatible schemas fall back to xattrs.
- Notifications include the first sharing warning (for example, Form editor
  links). Raycast also shows successful-command warnings.
- `doctor` and `open` share the same browser routing decision; terminal names
  and installation are checked by `doctor` and `popup`.
- Detached Terminal/iTerm2 launch failures are sent to the macOS system log
  under `drivethru` and shown in a notification, including Automation guidance.
- All public subcommands accept `--help` as their first argument; `help` is an
  alias for the general usage text.
- Exit 1 includes usage/configuration/action errors, missing paths and
  `search --copy-first` with no match. Exit 5 means a missing or failing
  dependency. Listing skips unreadable accounts with a warning and succeeds
  if at least one is readable; exit 6 means none are readable (or an explicit
  target is permission denied).

- Canonical path capture preserves trailing filename newlines. Human-facing
  terminal messages strip control characters, including OSC clipboard commands;
  raw list/search records retain filenames for programmatic use.
